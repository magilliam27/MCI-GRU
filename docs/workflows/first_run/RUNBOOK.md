# First admitted run on Colab: runbook

How to launch the first admitted run of the frozen recipe (map #187) from
`notebooks/first_run_colab.ipynb`. The notebook is generated by
`scripts/gen_first_run_colab_nb.py`; its logic lives in `scripts/first_run_colab.py`
and is tested in `tests/test_first_run_colab.py`. The charter and admission receipt
draft is [`ADMISSION_RECEIPT_AND_CHARTER_DRAFT.md`](ADMISSION_RECEIPT_AND_CHARTER_DRAFT.md).

## Once, before the first run

1. **Merge the open recipe pull requests in order:** #274, then #275, then the
   pull request that adds this runbook (#270 is already merged). In `full` mode the
   notebook checks the cloned commit for #270, #274 and #275 and names any that is
   missing.
2. **Put the EODHD S&P 500 file on Drive.** Copy the whole folder
   `C:\Users\magil\MCI-GRU\data\raw\market\eodhd_sp500_2010_20260919\` (it holds
   `sp500_index.csv` and the pull's `inventory.json`) into
   `My Drive/MCI_GRU_shared/preservation/`, beside the LSEG package folder rather
   than inside it, so that package's verified ten-file inventory stays as it was
   restored (#207). The file must end up at
   `My Drive/MCI_GRU_shared/preservation/eodhd_sp500_2010_20260919/sp500_index.csv`,
   351,815 bytes, SHA-256
   `9f5cfaf5e9f057065b83619b01568164e1f61a45df9453c66269fb54f080f5ac`. The
   notebook refuses any other bytes. Copy only; nothing in `data\raw` moves.
3. **Add the FRED key as a Colab secret.** In Colab, open the key icon in the left
   bar, add a secret named `FRED_API_KEY`, paste the key as its value, and turn on
   notebook access. The notebook reads it only from there and never prints it.

## Each run

1. Open `notebooks/first_run_colab.ipynb` from GitHub in Colab
   (File > Open notebook > GitHub, repository `magilliam27/MCI-GRU`, branch `main`).
2. Runtime > Change runtime type > a GPU.
3. In the parameters cell: leave `RUN_MODE = "full"` for the admitted run, or
   set `"smoke"` for a 1-model, 2-epoch mechanics check that is labelled not
   evidence. Set `EXPECTED_COMMIT` to the `main` commit you mean to run.
4. Runtime > Run all. The cells, in order:
   - mount Drive and load the FRED key from Colab secrets;
   - clone the repository (a second clone in the same runtime is refused:
     disconnect and delete the runtime to start again);
   - install `requirements.lock`, then the repository with `--no-deps`, and check
     that every pin is installed and a CUDA GPU is visible;
   - check the commit for #270, #274 and #275;
   - stage and verify the package and the EODHD file;
   - run the recipe (it stages and verifies again first), copying the run folder to
     `MyDrive/MCI_GRU_shared/runs/first_run/<run tag>/` every 10 minutes and at
     the end;
   - print where the outputs are.
5. Keep the browser tab open while it trains. `colab_heartbeat.json` in the Drive
   run folder shows when the last copy was made.

## When something stops

| Message | Meaning | What to do |
| --- | --- | --- |
| `Environment check FAILED` with `No CUDA GPU visible` on a GPU runtime | The PyPI `torch==2.12.1` wheel targets a newer CUDA driver than the runtime has | Set `TORCH_INDEX_URL` to a PyTorch wheel index for an older CUDA build of the same version (for example `https://download.pytorch.org/whl/cu128`), disconnect and delete the runtime, and run all again |
| `Environment check FAILED` listing packages | A pin did not install, or Colab's Python is not 3.12 | Read the list; do not run with a mismatched lock |
| `MISSING #270` / `#274` / `#275` | The commit lacks that pull request | Merge it, or run `smoke` for a mechanics check only |
| `Missing on Drive` or `does not match its pin` | A staged file is absent or has other bytes | Fix the Drive copy; never edit the pin to match |
| `run_failure.json` in the run folder | An input failed admission before training | Report it as it stands; do not edit inputs to get past it |
| The runtime disconnects | The run is incomplete | Start again from the top; the new run gets a new tag and folder |

## What the notebook changes in the clone

- Two of the package's sidecar `.json` files are tracked in git with LF line
  endings, while the package pins the CRLF bytes they were preserved with. Staging
  checks that the committed file with CRLF endings has exactly the pinned digest,
  marks those two paths `text eol=crlf` in the clone's `.git/info/attributes`, and
  has git check them out again, which writes those bytes. Git then reports no
  change. Any other difference stops.
- MLflow tracking is switched off (`tracking.enabled=false`): `requirements.lock`
  does not include the `tracking` extra, and the run's own records do not use it.
- `pip freeze` is saved as `pip_freeze.txt` in the run folder, because the lock
  does not list the Linux-only CUDA packages torch pulls in.

## Why the run writes to local disk first

Snapshot capture publishes each manifest with a hard link (`os.link`), and
Colab's Drive mount is not known to support hard links. So the run folder lives under `/content/mci_gru_runs/` and
is copied to Drive as it goes, from a background thread, so a slow or failed copy
never stops training; a failed copy is reported and retried at the next tick.
Copies only add or update files; nothing on Drive is ever deleted.
