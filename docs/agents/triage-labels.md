# Triage Labels

The Matt Pocock skills use **two category roles and five state roles**.
`triage/SKILL.md`: *"Every triaged issue should carry exactly one category role
and one state role."* Map them to these exact GitHub label strings:

**Category roles** — what kind of thing this is:

| Label in `mattpocock/skills` | Label in MCI-GRU | Meaning |
| --- | --- | --- |
| `bug` | `bug` | Something is broken |
| `enhancement` | `enhancement` | New feature or improvement |

**State roles** — where it is in the triage state machine:

| Label in `mattpocock/skills` | Label in MCI-GRU | Meaning |
| --- | --- | --- |
| `needs-triage` | `needs-triage` | Maintainer needs to evaluate this issue |
| `needs-info` | `needs-info` | Waiting on the reporter for more information |
| `ready-for-agent` | `ready-for-agent` | Fully specified and ready for an agent |
| `ready-for-human` | `ready-for-human` | Requires human implementation |
| `wontfix` | `wontfix` | Will not be actioned |

Before applying a canonical role, verify that its exact configured label
exists. If it is missing, create that exact label with an appropriate
description and continue the requested workflow. Never substitute a
semantically similar label or create a near-duplicate spelling.

When a skill names a triage role, use the corresponding exact string from these
tables.

Applying a category role is itself a triage act, so a state role is owed at the
same moment. An issue carrying `bug` or `enhancement` and no state role is
half-triaged; an issue with no labels at all normally goes to `needs-triage`
first.

`wayfinder:*` labels are **ticket-type** labels, not triage roles. They do not
satisfy the state requirement.

## Triage output must disclose that it was AI-generated

`triage/SKILL.md` requires that every comment or issue posted to the tracker
**during a triage workflow** begin with:

```text
> *This was generated by AI during triage.*
```

This applies to triage output specifically, not to every agent comment. As of
the audit that added this section it had effectively never been applied here —
the only issue comment carrying the disclaimer predated the plugin install.

## This file is the vocabulary, not the state machine

In several harnesses the triage skill can only be started by the human rather
than reached for by an agent; whether that is so in yours is a harness question.
When it *is* in play, prefer it — the full state machine runs.

This file is the operative substitute for the label **vocabulary** when it is
not. It is **not** a substitute for the state machine: the attention query, the
redundancy and prior-rejection checks, and the agent-brief and needs-info
templates all live in the skill and have no equivalent here.

Two consequences worth knowing rather than discovering:

- The skill's prior-rejection check reads `.out-of-scope/*.md`. **No such
  directory exists in this repository**, so that check silently no-ops. Note the
  skill also *writes* there when an enhancement is rejected.
- Ticket and specification shapes come from `to-spec` and `to-tickets`. Where
  those are not reachable either, "identically shaped tickets and specs" is not
  achievable by an agent working alone.
